# おさかなを英語で発音練習 — 設計書・引き継ぎ資料・作業手順書

この資料は、アプリの仕組み、設計上の約束、音声の作り直し方、テストと公開方法をまとめています。
オーナーは非エンジニアです。変更内容と確認できていないことを日本語で説明してください。

- 公開URL：https://okatech.github.io/agent-textbook/sea-creatures/
- リポジトリ：`okatech/agent-textbook`
- アプリの場所：`sea-creatures/`
- 制作：アーヒスタ制作
- 更新日：2026年10月30日

## 1. 目的と対象

海の生き物12種類のアメリカ英語を、聞いて発音練習するアプリです。
iPhone Safari と Android Chrome を優先します。画面は日本語、英単語・発音記号は英語です。

shark（サメ）／dolphin（イルカ）／penguin（ペンギン）／sea turtle（ウミガメ）／
ray（エイ）／jellyfish（クラゲ）／hammerhead shark（シュモクザメ）／orca（シャチ）／
mackerel（サバ）／clownfish（カクレクマノミ）／sardine（イワシ）／bonito（カツオ）

## 2. 機能

1. カードを押すと、その単語の音声ファイルを再生します。
2. 女性は **Ava**、男性は **Andrew**。声はそれぞれ1種類だけです。
3. 声の切り替えは設定変更だけです。再生中の音は止めますが、新しい音は鳴らしません。
4. 「詳しく見る」は発音記号、音節、強勢、発音のコツ、豆知識を表示します。開くだけでは音は鳴りません。
5. 詳細画面の「聞く」でその単語を再生します。「閉じる」、背景タップ、Esc で閉じます。
6. 声の設定を端末に保存します。保存できない場合も利用は続けられ、画面に理由を表示します。
7. 通信・再生エラー、アプリ内ブラウザなど、必要な場合だけ注意を表示します。
8. アイコン・名前付きでホーム画面に追加できます。ただしオフライン動作は保証しません。

録音・マイクへのアクセスや発音採点の機能はありません。利用者の音声を外部送信しません。
Azure への接続は開発時の音声生成・検証だけで、公開アプリからは接続しません。

## 3. 守る設計ルール

- **ボタンは書いてあることだけをする。** 声変更・詳細表示で自動再生しない。
- **シンプル第一。** 声の種類や設定項目を増やさない。
- **発音の正確さを優先。** 辞書の米語に合わせ、認識結果だけで発音の正誤を断言しない。
- **できないことは正直に表示。** 失敗を無視したり、端末の別音声へ黙って切り替えたりしない。
- 既存の青いデザイン、丸いピル型の操作ボタン、高さ44px以上を維持する。
- 音声生成キー・トークンをソース、公開ファイル、ログ、チャットに出さない。

過去に削除した「米・英・豪・印アクセント」「速さ選択」「声変更時のお試し再生」
「詳細表示時の自動再生」は復活させていません。追加する場合はオーナーの確認が必要です。

## 5. コードの仕組み

### 5-1. 生き物データ

`CREATURES` 配列に情報をまとめています。

```js
{
  id: "sardine", word: "sardine", ja: "イワシ",
  ipa: "/sɑːrˈdiːn/",
  syl: ["sar", "dine"], stress: [1],
  tip: "発音のコツ", fun: "豆知識"
}
```

`id` は画像名と音声ファイル名に使います。`stress` は強く読む音節の番号（0始まり）です。
`tip` と `fun` は作者が用意したHTMLで、`<b>` を使用できます。
文字列中の引用符は適切にエスケープするか、全角の “ ” を使ってください。
音声生成スクリプトもこの配列から12語を読み取ります。表記を変更した場合は生成処理も確認します。

### 5-2. 音声

以前の `speechSynthesis`、声一覧取得、名前による男女推定、pitch調整は削除しました。

- 女性 `en-US-AvaNeural`、男性 `en-US-AndrewNeural` の事前生成MP3を使います。
- 形式は `audio-24khz-48kbitrate-mono-mp3`。
- `speak(creature, button)` はタップ処理の中で直接 `Audio.play()` を呼びます。
- 再生ごとに別の `Audio` 要素を作り、前の音声を停止・解放します。
- `current` と再生セッションを照合し、古い終了通知・Promise拒否が新しい再生に影響しないようにします。
- 読み込み中・再生中を表示し、終了・エラー・停止時に表示を解除します。
- 12秒経過しても終わらなければ停止し、通信確認と再試行を案内します。
- `onpause` で終了扱いにしません。端末によって、エラーより先にpauseが届くためです。
- 詳細の開閉、声変更、別アプリへの切り替え、ページ離脱で `stopPlayback()` を呼びます。
- 再生失敗は一覧画面にも詳細画面にも表示します。失敗時に端末読み上げへ切り替えません。

### 5-3. 画面と保存

- `renderGrid()`：12枚のカードと名前付きの「詳しく見る」ボタンを作ります。
- `openDetail(c, trigger)`：音は鳴らさず詳細を開き、一番上から表示します。
- ダイアログに読み上げ用のタイトルを設定し、閉じたら元のボタンへフォーカスを戻します。
- ダイアログの内側の余白・スクロールバーを背景タップと取り違えないよう座標を確認します。
- 保存キー `seaPron`、値 `{"gender":"female"}` または `{"gender":"male"}` を維持します。
- 保存値の破損・ストレージ利用禁止でアプリ全体が停止しないようにしています。
- 幅320pxでもカード2列。長い英単語・発音記号は折り返します。
- ダークモード、キーボードフォーカス、動きを減らす設定に対応します。

## 6. 音声生成と結果の読み方

### 今回の音声

24個すべてを生成し、MP3からWAVに戻して長さと音声認識を確認しました。
各ペアの男女ファイルは異なり、長さは0.3〜3秒の範囲です。詳細は `audio/verification.json` に記録しています。

**重要：自動音声認識の完全一致は23/24です。**

女性の `bonito` は、単語を指定しない認識では人名の `Benito.` と出力されました。
この単語には米語IPA `bəˈniːtoʊ` をSSMLで指定しています。
同じMP3を復号した音声について、正解語を `bonito` と指定する別の発音評価では
AccuracyScore **100/100** でした。

正解語を指定した評価は、独立した音声認識の完全一致とは違います。
この1件は `recognitionExactMatch: false`、`humanReviewRequired: true` として残しています。
機械に単語を当てさせるために発音を不自然に変えないこと。公開前にこの例外をオーナーへ説明し、
実際に聞いてもらってください。自動テストの合格を「発音もすべて人間が確認済み」と表現しないでください。

全24音声について、最終的な聞こえ方・自然さ・アクセントは実機と人の耳で確認が必要です。

### 生成の前提

Python 3、ffmpeg、Azure Speechを利用できるリソースが必要です。
既存のS0リソースを使う場合、音声合成・音声認識・発音評価の従量料金が発生します。
再生成にはAzureへの接続が必要ですが、テスト・公開・通常のアプリ利用にはAzureの認証は不要です。

認証は次のいずれかを開発環境の環境変数で設定します。値をチャットやGitに貼らないでください。

| 方法 | 必要な設定 |
|---|---|
| APIキー | `AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION` |
| Entra認証 | Azure CLIで対象にサインインし、`AZURE_SPEECH_RESOURCE_ID`、`AZURE_SPEECH_ENDPOINT` |

Entra方式のエンドポイントは `https://<resource>.cognitiveservices.azure.com/` です。
CLIは指定リソースのサブスクリプションを明示してトークンを取り、既定の接続先を変更しません。
キー認証が無効なリソースでも、必要なSpeech利用権限があればEntra方式で利用できます。
権限が不足した場合、勝手に認証設定・アクセス権限を変更しないでください。
ffmpegがPATHにない場合は `FFMPEG_PATH` で実行ファイルのパスを指定します。

リポジトリのルートで実行します。

```powershell
python .\sea-creatures\_tools\generate_audio.py
```

スクリプトは声名の存在・言語・性別を確認し、24ファイルを一時フォルダに生成します。
MP3を16kHzモノラルWAVへ復号し、長さと音声認識、男女のSHA-256差分を確認します。
予期しない認識不一致・通信エラー・範囲外の長さはエラーで停止し、既存の公開用音声を変更しません。
既知の `bonito` / `Benito` だけは正解語付き発音評価が95以上の場合に要確認として保存します。
最後に件数と要確認件数を必ず出力します。完了表示だけで公開可と判断しないでください。

キー・トークン・Azureリソースの識別情報は音声や検証JSONに保存しません。

## 7. テスト

Node.js 22以上を用意し、次のコマンドを実行します。

```powershell
Set-Location .\sea-creatures\_tests
npm ci
npx playwright install chromium webkit
npm test
```

Linuxではブラウザ導入時に `npx playwright install --with-deps chromium webkit` を使います。

24テストをChromium・WebKitの両方で実行します（合計48ケース）。

- 全12語×男女のファイル参照、音声のSHA-256、生成結果の整合性
- 声変更・詳細表示で音が鳴らないこと、全12詳細からの再生
- 連続タップ、古い終了通知・Promise拒否、声変更時の停止
- 読み込み失敗、再生拒否、再試行、タイムアウト、詳細内のエラー表示
- 背景移行・ページ離脱時の停止
- 閉じる、Esc、背景タップ、フォーカス復帰、内側の余白の扱い
- 壊れた保存値、不正な声名、保存禁止、LINE内ブラウザの案内
- 幅320／375／390／412pxの明暗表示、長いタイトル・IPAの折り返し
- 全24MP3の実デコード、音量がゼロでないこと、画像読み込み
- 実際のAudio要素による再生・終了・404・再試行（モックだけではない）

Windows版Playwright WebKitはWeb Audio APIを公開しないため、24MP3をWeb Audioで
デコードする1ケースだけ明示的にスキップします。Chromiumでは実行し、LinuxのGitHub Actionsでは両方で実行します。
WebKitはSafariと同じエンジンですが、iPhone実機テストの代わりではありません。

実機での最終確認：

1. iPhone SafariとAndroid Chromeで、男女それぞれの12語を聞く。
2. 特に女性のbonitoを聞き、発音記号・真ん中の強勢と合っているか確認する。
3. 連続タップ、イヤホン切替、バックグラウンド移行、詳細の開閉を確認する。
4. 通信を切ったときに、鳴らないまま成功扱いにならないことを確認する。
